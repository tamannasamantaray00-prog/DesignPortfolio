Context

Landmark Group runs eight retail brands, from Babyshop to Centrepoint, and every one of them needs its own identity sitting on top of shared patterns for product pages, baskets and checkout. That is a real tension to design for: enough shared structure that eight teams are not rebuilding the same button from scratch, but enough flexibility that Max does not end up looking like Babyshop.

The problem

Build a design system that eight brand teams could genuinely share, without flattening what makes each brand distinct. It had to work for designers and for the engineers consuming it, documented clearly enough that neither side needed to ask the other what a token meant.

What I built

Three pieces that work together, built on eight design principles: Shared Language, Consistency, Reusability, Scalability, Maintainability, Accessibility, "One System, Many Brands," and Shared Responsibility.

1. A tokenised, multi-brand foundation

Eight brands sharing components only works if the components themselves do not know which brand they are in. I built LDL on a two-layer token system: primitive tokens hold raw values — colors, spacing, radius — and semantic tokens map those to design intent, like surface, primary and accent. Components consume the semantic layer as Tailwind utilities, and never touch a raw variable directly.

That split is what makes brand-switching possible without touching a single component: semantic tokens resolve to each brand's primitive values at runtime, so switching brands only ever changes the variable mode underneath. Over 200 tokens now sit behind the system, shared across all eight brands.

2. Live, interactive documentation

A design system that nobody reads is just a Figma file. I wanted LDL's documentation to feel like a real product, so I designed and coded it myself rather than handing it to engineering as a spec: a three-column layout, global search with a Cmd+K shortcut, a token table that filters and highlights matches as you type, and type specimens that switch live between brands so you can actually see the typography shift, not just read about it.

3. A plugin that syncs tokens to developers

Tokens that live only in Figma are a promise, not a system — someone still has to translate them into code by hand, and that gap is where drift creeps in. I co-created a plugin with an engineer that syncs token updates straight to developer repositories, so a color or spacing change in the system does not need a manual hand-off to reach production.
